# 容器镜像发布流程强化

本工作流改动独立于容器运行强化和 Compose 改动，不修改 Dockerfile、启动行为、挂载或服务配置。维护者可以只接受运行强化，而不采用本发布流程改造。

## 触发与验证

- 匹配 `v*.*.*` 的版本标签以及手动触发会运行 Docker 流程。仅修改文档的标签推送不发布镜像。分支推送不发布镜像；开发构建仍属于 fork 层面的事情。
- PR 只运行验证，不能登录 GHCR 或发布 package；只有发布 job 请求 `packages: write`，其他 job 只读仓库。
- Linux AMD64 和 ARM64 runner 分别安装锁定依赖，运行 lint、服务端及桌面类型检查、完整测试集并原生构建镜像；两者通过后才能发布。
- 若独立的容器 PR 已合入 `docker-compose.yaml` 和 `tests/docker-smoke.test.ts`，发布前还会执行 Compose 及容器生命周期检查；文件尚不存在时，对应步骤明确跳过，不能将构建成功视为生命周期测试通过。bind mount 覆盖配置存在时也会校验。
- 发布包含 AMD64 / ARM64 的 GHCR 多架构镜像，并生成构建来源证明和 SBOM；它们不替代漏洞扫描、签名或仓库权限控制。旧流程安装了 cosign 但从未执行签名，本流程移除该无效步骤，也不宣称提供镜像签名。

## 镜像名称与标签

镜像名称根据仓库名转小写生成：`ghcr.io/<owner>/copilot-api`，不硬编码个人镜像仓库。

| 来源 | 标签 |
| --- | --- |
| 稳定标签 `v2.5.3` | `v2.5.3`、`v2.5`、`v2`、`2.5.3`、`2.5`、`2`、`latest`、`sha-<完整提交 SHA>` |
| 预发布 `v2.6.0-beta.1` | `v2.6.0-beta.1`、`2.6.0-beta.1`、`sha-<完整提交 SHA>`；不更新稳定滚动别名和 `latest` |

保留已有的带 `v` 版本标签，并增加无 `v` 别名。`latest` 保持只跟随最新稳定版本。提交标签方便追溯；需要不可变部署标识时，应固定镜像 digest。显式 `prefix=v` 写法保证预发布保留 `v` 前缀，否则 `docker/metadata-action` 会将其丢弃。

并发按 Git ref 隔离，不同版本标签不会相互取消，标签运行不会被取消。手动重跑旧版本或手动触发可能重新发布旧标签，维护者应将手动触发／重跑权限视为发布权限。

## 希望维护者确认

每次发布的原生 ARM64 验证成本是否可接受，以及是否需要无 `v` 标签别名。本提案刻意保持现有的"仅发布版本"范围：不引入开发分支镜像，也不引入 latest 渠道配置。工作流改动不会自动替换任何现有部署的镜像或数据目录。
